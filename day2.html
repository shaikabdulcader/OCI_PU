Castle AnalogyMoat → Walls → Gate → Guards → King. Each OCI layer above is labelled with its castle equivalent — even if the moat is crossed, the walls remain. The king (your data) is only lost when every defense fails.

Common TrapDefense in depth doesn't mean "add more tools" — it means independent controls at different layers, so a single misconfiguration (e.g. a public bucket) isn't the only thing standing between an attacker and your data.
03Security Fundamentals

Zero Trust

"Trust nobody. Verify everyone. Every time." Like airport security — even VIPs show a passport and get their bags scanned.

Click play to step through Zero Trust evaluation for a single access request.

🏰 Traditional (perimeter) model

Inside network → trusted. One VPN login unlocks broad access; one breach means free movement everywhere.

🛡 Zero Trust model

Every request re-verifies identity, device posture, and risk — regardless of network location, every time. OCI: IAM authentication, MFA, Identity Domains, Dynamic Groups, Policies.

04Security Fundamentals

Shared Responsibility — Security Lens

Oracle secures the cloud; you secure what you deploy. Switch the service model and watch the responsibility boundary line physically move through the stack.

CUSTOMER you configure & secure it SHARED both hold a piece ORACLE Oracle runs & secures it

🎯 Incident Drill — who's responsible?

Real exam questions look exactly like this: an incident happens, you name the responsible party. Answer all five.

1. Your database password was weak and got brute-forced. Data was stolen.
💥 Customer. Credentials, users and IAM policies are always yours — Oracle cannot pick your passwords. This is THE classic exam trap.
2. A power failure takes down a data center hall in an Availability Domain.
🏢 Oracle. Physical security, power, cooling and hardware are always Oracle's side. (But architecting across ADs so the failure doesn't hurt you — that's on you.)
3. A storage bucket was configured public; customer records leaked.
🪣 Customer. Resource configuration and data protection are customer-side. (Day-2 tools that would have saved you: Security Zones to block it, Cloud Guard to catch it.)
4. A vulnerability in the hypervisor itself is exploited.
⚙️ Oracle. The virtualization layer belongs to Oracle in every service model — customers never touch the hypervisor.
5. An unpatched operating system vulnerability is exploited.
🖥 It depends on the service model. IaaS: you patch the OS → customer. PaaS/SaaS: Oracle runs the OS → Oracle. This is why the boundary line above moves!

0 / 5 answered.

💥
Exam TrapWhatever the model, four things NEVER leave the customer's side: your data, your users, your IAM policies, your configuration choices.

15Cost Management

BYOL vs License Included — Decision Machine

Think of it like a car with a driving licence: License Included = the rental company provides a licensed driver (easy, costs more). BYOL = you already hold a licence, so you just rent the car (cheaper). Answer two questions and let the machine decide.

1 · Do you already own the license (with active support)?
2 · Workload size — 8 OCPUs
✓ RECOMMENDED
📦 License Included
—
Oracle's license bundled into the hourly rate. Nothing to prove, nothing to audit — just start. Best for new customers.
✓ RECOMMENDED
🎫 BYOL — Bring Your Own License
—
You pay only for infrastructure; your existing license covers the software. Best for existing customers.
🎓
Exam TipThe two triggers to memorize: "already own licenses with active support" → BYOL, lower cost. "new customer / simplest setup" → License Included. Never recommend BYOL to someone who'd have to buy a license first.

23Wrap-Up

Cheat Sheets

Security

  • CIA = Confidentiality, Integrity, Availability
  • Defense in Depth = layered, independent controls
  • Zero Trust = never trust, always verify
  • Shared Responsibility = Oracle secures the cloud; you secure what you deploy

Cloud Guard

  • Pipeline: Resources → Targets → Detectors → Problems → Responders → Notifications
  • Lifecycle: Open → Investigating → Resolved → Closed
  • Zones block; Guard detects + responds; Advisor recommends

Cost Management

  • Budgets alert at 50/80/100% — they don't hard-stop spend
  • BYOL saves money if you already hold licenses
  • Right-size: match OCPUs to actual usage

Governance

  • Limits = Oracle ceiling (support request to raise)
  • Quotas = self-imposed cap per compartment
  • Organization Mgmt links tenancies for billing, not IAM
  • Compliance: ISO 27001 · SOC 1/2 · PCI DSS · HIPAA
