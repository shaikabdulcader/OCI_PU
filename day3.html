01Linux Architecture

Linux Architecture & Kernel

Linux began in 1991 as Linus Torvalds' hobby kernel, paired with GNU userland tools to form a complete OS. Oracle Linux, Ubuntu, RHEL, CentOS, and Debian are all distributions built around this same kernel.

What the kernel actually manages

⏱ Process Scheduling

Decides which process runs on which CPU core, and for how long.

🧠 Memory Management

Allocates and isolates RAM between processes via virtual memory.

📁 File System

Presents devices and storage as a unified directory tree.

🌐 Networking & Drivers

Handles the network stack and talks to hardware via drivers, servicing system calls and interrupts from user space.

🎓
Exam TipOracle Linux is built to be a drop-in, ABI-compatible alternative to RHEL, and offers the free Unbreakable Enterprise Kernel (UEK) — a common exam distinction point vs stock RHEL/CentOS.

04Users & Permissions

Users & Groups

Every process runs as a UID/GID. root (UID 0) bypasses permission checks entirely — sudo grants temporary root-equivalent access.

UID / GID

Numeric identifiers for a user and its primary group.

Home Directory

Default working directory, usually /home/<user>.

Login Shell

The program started on login, typically /bin/bash.

sudo

Grants a normal user temporary elevated privileges, logged and auditable — safer than sharing the root password.

06Processes & Services

Processes & systemd

Every running program is a process with a PID and a parent PPID. systemd manages long-running services.

Foreground

Occupies the terminal, blocking further input until it exits.

Background

Runs detached from the terminal, launched with a trailing &.

Zombie

Finished but not yet reaped by its parent — still holds a PID entry.

Daemon

A background service with no controlling terminal, usually started at boot.

ARP, Routing & Switching

Three mechanisms that get a packet from A to B on a local and routed network.

🔍 ARP

Resolves an IP address to a MAC address on the local segment before a frame can be sent.

📡 Routing

A router forwards packets between networks using its routing table.

17Cloud Shell & CLI

CLI Configuration & Authentication

The CLI reads ~/.oci/config for a profile's region, user, and key fingerprint.

[DEFAULT] user=ocid1.user.oc1..aaaaaaaa... fingerprint=a1:b2:c3:d4:e5:f6:... key_file=~/.oci/oci_api_key.pem tenancy=ocid1.tenancy.oc1..aaaaaaaa... region=us-ashburn-1 # default profile

Authentication methods

API Keys / Config File

A local RSA key pair; fingerprint + private key referenced from ~/.oci/config. Best for CLI/SDK use from your own machine.

Session Token

Short-lived token from an SSO login (oci session authenticate) — no long-lived key on disk.

Instance Principal

A compute instance authenticates as itself, no embedded credentials — ideal for code running on OCI compute.

Resource Principal / Dynamic Group

Non-compute resources (like Functions) authenticate via a Dynamic Group's matching rule, scoped by IAM policy.

24Wrap-Up

Cheat Sheets

Linux

  • rwx = 4+2+1; owner-group-others
  • chmod 777 = world-writable, avoid
  • Zombie = finished, not yet reaped by parent

Networking

  • TCP = reliable/ordered; UDP = fast/best-effort
  • /24 = 256 addresses, 254 usable hosts
  • DNS: Browser → Cache → Root → TLD → Authoritative

CLI

  • oci <service> <resource> <action>
  • Config lives at ~/.oci/config
  • Instance principals need no embedded key

API / SDK

  • 2xx success · 4xx client error · 5xx server error
  • 429 = rate limited; back off and retry
  • Console/CLI/SDK are all wrappers over the same REST API
